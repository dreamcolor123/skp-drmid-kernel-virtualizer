## 6. 系统稳定性与停止

压力后：

```text
sys.boot_completed: 1
Activity service: found
SurfaceFlinger service: found
system_server / surfaceflinger: alive
```

最近内核日志未出现新增 Oops、panic、hung task、soft/hard lockup、UAF 或越界报告。

通过 DRMIPC19 v4 发送 `STOP` 后：

```text
STOP result: 0
daemon absent: 3 秒内
drmid_control_v4.sock absent: 3 秒内
```

源码固定按 TEE Hook、Binder parser Hook 的顺序移除；管理器日志未出现 TEE 移除
失败，并确认 parser Hook 已移除、模块结果为 OK。
停止瞬间有一个阻塞中的 Binder ioctl，因此约 97864 字节 Kernel Context 按既有防
UAF 设计保留到下一次重启；Hook 已不再可达。这是内存生命周期状态，不是磁盘文件
残留，也未影响系统服务。

已删除本轮 `/data/local/tmp` 下的候选 ZIP、runner、resolver 状态目录及两个临时
探针。run-once 私有配置保留 seed/profile，以便下一轮 Write 验收保持同一虚拟 ID。

## 7. 结论

`1.3.0-rc1` 在当前 Linux 6.12 / Android 16 设备的首轮 Dry-run 真机验收通过：

- SDK run-once、启动门控、ABI 19 与 v4 IPC 通过；
- Binder 标准路径和 OEMCrypto/SMCInvoke 直连路径均按预期命中；
- TEE 后端对调用身份全局生效，同时保持 Widevine TA 对象链约束；
- 短压力计数严格闭合，对象释放、错误计数和系统响应正常；
- 正常 STOP 与临时文件收口通过。

本轮保持 Dry-run，没有执行任何虚拟 ID 字节写入。下一轮应复用同一候选与持久
profile，单独切换 Write，分别验证 MediaDrm 与 OEMCrypto 直连结果匹配同一活动
虚拟 ID，并在完成后恢复 Dry-run。
