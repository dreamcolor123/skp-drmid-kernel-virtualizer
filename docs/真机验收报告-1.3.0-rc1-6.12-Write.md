## 4. 多调用身份与连续读取

三组逐字节匹配结果：

| 路径 | 调用身份 | 读取次数 | 结果 |
|---|---:|---:|---|
| MediaDrm | EUID 0 | 100 | stable / expected_match=yes |
| AIDL DRM | EUID 2000 | 100 | stable / expected_match=yes |
| OEMCrypto 直连 | EUID 0 | 50 个会话 × 2 | stable / expected_match=yes |

AIDL Fixture 在降权前读取 root/0600 期望值，随后 `setuid(2000)`，完整 100 次比较
均在 EUID 2000 下完成。该结果与 TEE Hook 日志中的 `euid-filter=absent` 一致。

OEMCrypto 最初使用无间隔的 50 个独立进程反复初始化/终止，触发 SMCInvoke 服务端
异步释放窗口；这是测试夹具的会话抖动，不是 ID 比较或 Hook 写入错误。停止加压后
单次调用立即恢复。加入 200 ms 会话间隔后：

```text
预检: 10/10 会话通过
正式: 50/50 会话通过
正式读取: 100/100 expected_match=yes
TEE op9_write_ok: 69 -> 169（精确 +100）
TEE op9_write_faults: 0 -> 0
```

内核日志只出现正常的 `server_release` / `server destroyed` 生命周期记录，没有
SMCInvoke fault、Oops 或锁死。后续直连 Fixture 应保持会话间隔，或改成单进程内
连续读取，避免把 transport 生命周期混入 Hook 验收。

验收后已完成单进程优化：`oemcrypto_direct_probe` 新增 `DRMID_REPEAT=1..1000`，
一个 Initialize/Terminate 会话内完成全部读取。当前设备在模块停止状态下执行
`DRMID_REPEAT=100`，100/100 稳定，耗时约 520 ms；SMCInvoke `server_release`
只增加 2 条服务对象释放记录。详细结果见
`docs/OEMCrypto直连探针单会话优化-20260823.md`。
